# job_fit — Agent Guide

Repo: `milestones95/job_fit` — a personal job-fit finder. It pulls job postings
from the public APIs of Greenhouse / Ashby / Lever boards for a configured list
of companies, filters them by title, scores each survivor against an "ideal
role" description with one OpenAI chat-completion call per posting, and renders
a ranked HTML dashboard.

## Stack

- **Language:** Python 3.13 (plain scripts, no framework)
- **Third-party deps:** `requests` (ATS API fetches), `openai` (title expansion
  + per-job scoring) — installed via pip; there is no requirements file yet
- **Web:** Python stdlib `http.server` (`feedback_server.py`) serving one
  generated static page (`jobs_dashboard.html`, inline CSS/JS)
- **Storage:** no database; two JSON caches in the repo root
  (`target_titles_cache.json`, `job_score_cache.json` — both gitignored)
- **External services:** OpenAI API (needs `OPENAI_API_KEY`); public
  Ashby / Greenhouse / Lever job-board APIs (no auth)

## Commands

| Action | Command |
|---|---|
| Install deps | `pip install openai requests --break-system-packages` |
| Run the dev server | `python feedback_server.py` |
| Open the app | http://localhost:8765/jobs_dashboard.html |
| CLI pipeline (interactive) | `python job_fit_finder.py` |
| Rebuild dashboard from cache | `python build_dashboard.py` |

- Dev server port: **8765** (`PORT` constant in `feedback_server.py`), bound to
  `localhost`.
- API endpoints: `POST /api/analyze` (body `{"titles": "...", "ideal_role":
  "..."}` — LLM-expand titles, fetch, score, rebuild dashboard) and
  `POST /api/show_all` (fetch every posting, no LLM, rebuild unscored).

## Environment variables

| Var | Required | Notes |
|---|---|---|
| `OPENAI_API_KEY` | yes | Loaded from a `.env` file next to the scripts (gitignored) or the shell env. Any non-empty value lets the server start; a real key is required for the Analyze / LLM-scoring flow. |
| `JOB_FIT_EXPAND_MODEL` | no | Title-expansion model, default `gpt-4o-mini` |
| `JOB_FIT_SCORE_MODEL` | no | Scoring model, default `gpt-4o-mini` |

## Gotchas

- `jobs_dashboard.html` is tracked but regenerated by the app — run
  `git checkout -- jobs_dashboard.html` to drop incidental rebuilds before
  committing.
- `OPENAI_API_KEY` is read at import time (`os.environ["OPENAI_API_KEY"]`) —
  the server will not start without it set, even for the LLM-free flows.
- With a dummy key, `/api/analyze` still returns 200: LLM expansion falls back
  to the literal typed titles and every job scores 0% with an inline
  `[scoring error: 401]` note (by design — `score_job` never raises).
- Delete `target_titles_cache.json` to re-enter search titles.
- No test suite, no lint config. `ruff check --select E,F .` reports ~52
  style findings (informational only).
